## What EON is

**One Brain, Multi Decision Layer for the Epal ERP** (`erp.epal.com.bd`, Laravel 12 / MySQL, 12 companies).
Target: presented at **AI Business Summit 2026**, China–Bangladesh Friendship Conference Center, Dhaka (tech leaders, ministries, the PM). EON serves the boss: ask by voice or text → grounded answers with numbers, the rule applied, and the recommended action, across accounts (chart of accounts, GL, journals, ledgers), payroll, HR, expenses, CRM, tasks, employee monitoring/evaluation; a ranked morning brief; an approvals queue; drafts (reminders, warnings, notices).

## Stack — polyglot on purpose (owner's decision, 2026-08-18)

| Layer | Language | Where |
| --- | --- | --- |
| API, ERP DB access, memory, auth, cron, LLM agent | PHP 8.2 (plain, Laravel-compatible; later a Laravel `eon` module inside the ERP) | `server/` on Hostinger, next to the ERP |
| Heavy analytics/ML: forecasting, anomaly detection, evaluation model, Bangla/English NLP, Excel/PDF reports | Python (`server/py/`, called by PHP/cron, JSON in/out) | Hostinger SSH python3 or a VPS |
| Set-based computation (aging, TB, rollups) | SQL / MySQL | ERP database (read-only user) |
| Face: companion, voice capture/speech, screens, offline fallback | JavaScript | `ai-companion/`, `app/` |

Language model: **none, by the owner's decision (2026-08-19)** — no Anthropic key is configured or planned. `Brain::askLlm` stays in place for the day one is added, but the shipping brain is the offline one: `Nlu` → `Answer` → `Analytics`/`Insight`/`Tools`, PHP over the live ERP. See "No language model" below.

## The command space (2026-08-19)

EON composes rather than enumerates. `Nlu` scores the idioms people really say;
anything else falls through to `Grammar`, which reads a sentence structurally:

- **verb × subject** — "how much / show / rank / compare / where is / remind" pointed at
  one of ~45 ERP subjects, routed by a single table (`Grammar::SUBJECTS[…]['by']` overrides
  the default intent per verb, so *rank employee* → `staff_ranking` while *know employee* →
  `evaluate_person`).
- **instance × aspect** — a named record (661 of them: 87 staff, 24 parties, 68 passengers,
  29 projects, 8 companies, 445 accounts) plus one of 16 aspects. `person_aspect` answers
  any aspect of any employee from a single `Analytics::person()` dossier; `record_aspect`
  does the same for the other kinds. Naming a record and getting the list screen back reads
  as EON not having heard the question, so every kind answers about the record itself.
- **Bangla names reach Latin records** through `Grammar::skeleton()` — a consonant skeleton
  with vowels *and* the h of romanised digraphs dropped, because বাংলা শ gives "s" where the
  passport spells it "sh"; Rashedul and রাশেদুল only meet once both go.

| runner | walks | size | answering |
| --- | --- | --- | --- |
| `tools/matrix-run.php` | subject × verb × script | 435 | **100%** (68.3% before composition) |
| `tools/instance-matrix.php` | record × aspect × phrasing × script | **120,105** | **100%** on a 1,500-point stratified sample |

- **Line endings are mixed in this repo** — `Analytics.php`, `Erp.php` and `Nlu.php` are committed CRLF, most other files LF. Editing with a tool that rewrites newlines turns the whole file into one diff; match the committed style before staging (`git show HEAD:<file> | tr -cd '\r' | wc -c` tells you which it is).
- `tools/erp-map.mjs` needs Laravel's route table to produce anything useful: without `--routes` it writes `routes: 0`. Point `erp/.env` at a database it can boot against, run `php artisan route:list --json > routes.json`, then `node tools/erp-map.mjs --routes routes.json` → 1,376 routes.

- **`exec`/`shell_exec`/`proc_open` are disabled** for the web user. post-deploy does everything in-process; composer for the ERP was run once over SSH (`deploy/erp-install.sh`).
- **`.user.ini` is ignored** in our folder (PHP reads it only from the website's own root, which is gulfrabit.com's). PHP directives go in the site `.htaccess` as `php_value` (LiteSpeed honours them). `embed/check.php` shows what PHP accepted.
- **`auto_append_file` never reaches the client** behind Laravel (it terminates the request itself). The injector runs as **`auto_prepend_file`** and adds the tag from an output-buffer callback (`embed/eon-inject.php`).
- Reserved root names in `.htaccess` must be only EON's real paths — reserving `vendor` once swallowed the ERP's `public/vendor/alpine.min.js` and the ERP rendered unstyled.
- The ERP database on the host is `u239665931_eon` (the full dump `ERP Database.sql`); the ERP's `.env` is generated from EON's `server/config.local.php` db block. `public/uploads/` from the old server is **not** copied yet (user-uploaded files will 404 until it is).
- Cron: `deploy/deploy.sh --quiet` every minute; push → live in ~60 s (`health.php` shows the commit; the panel footer shows `build …`).
