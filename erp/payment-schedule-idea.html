Payment Schedule System – Design Idea

Due Date Tracking · Daily Schedule · Boss Approval · Reschedule  |  For Payables & Receivables

Core Idea: Each payable/receivable entry gets a due_date. A new Payment Schedules page shows today's dues, lets you submit the list to your boss for approval, and lets you reschedule any missed dates. The whole flow is linked back to your existing journal_entries table via a new payment_schedules table.

2
Database — New Table: payment_schedules
-- New migration: create_payment_schedules_table.php
Schema::create('payment_schedules', function (Blueprint $table) {
    $table->id();
    $table->foreignId('company_id')->constrained();
    $table->foreignId('journal_entry_id')->constrained(); // links back to journal
    $table->foreignId('journal_item_id')->nullable()->constrained(); // specific line item

    $table->enum('type', ['payable', 'receivable']);
    $table->string('party_type');           // 'customer' | 'supplier'
    $table->unsignedBigInteger('party_id')->nullable(); // customer_id or supplier_id
    $table->string('party_name');           // stored name (in case record deleted)
    $table->string('reference')->nullable();  // invoice/bill reference
    $table->decimal('amount', 15, 2);

    $table->date('due_date');                // current scheduled date
    $table->date('original_due_date')->nullable(); // first due date before any reschedule
    $table->unsignedTinyInteger('reschedule_count')->default(0);
    $table->string('reschedule_reason')->nullable();

    $table->enum('status', [
        'pending', 'submitted', 'approved',
        'rejected', 'paid', 'overdue', 'rescheduled'
    ])->default('pending');

    $table->foreignId('approved_by')->nullable()->constrained('users');
    $table->timestamp('approved_at')->nullable();
    $table->string('approval_note')->nullable();

    $table->foreignId('created_by')->constrained('users');
    $table->text('notes')->nullable();
    $table->timestamps();
    $table->softDeletes();
});

-- Also add reschedule history table (optional but recommended)
Schema::create('payment_schedule_logs', function (Blueprint $table) {
    $table->id();
    $table->foreignId('payment_schedule_id')->constrained();
    $table->enum('action', ['rescheduled', 'approved', 'rejected', 'paid']);
    $table->date('old_date')->nullable();
    $table->date('new_date')->nullable();
    $table->string('reason')->nullable();
    $table->foreignId('done_by')->constrained('users');
    $table->timestamps();
});

6
Implementation Plan — Step by Step
1
Migration

Run php artisan make:migration create_payment_schedules_table and create_payment_schedule_logs_table. Schema is shown in Section 2 above.

2
Models

Create PaymentSchedule and PaymentScheduleLog models. PaymentSchedule belongsTo JournalEntry, Company, User (approved_by). Add hasMany(PaymentSchedule::class) on JournalEntry model.

3
Modify Opening Balance Store Logic

In your journal store controller, after saving the JournalEntry, loop through the items array. If type = opening_balance AND the item has a due_date + party_id, create a PaymentSchedule record automatically. Add due_date, party_type, party_id, party_name to each row's payload.

4
PaymentScheduleController

New controller with these methods: index() — list with filters (date, type, status), approve() — set status=approved + approved_by + approved_at, reject() — set status=rejected + note, reschedule() — update due_date, log old date to history table, markPaid() — set status=paid, optionally create payment journal.

5
Overdue Auto-detection

Add a scheduled command: php artisan make:command MarkOverdueSchedules. Run daily via scheduler — marks all status=pending records where due_date < today as status=overdue. Register in app/Console/Kernel.php: $schedule->command('schedules:mark-overdue')->dailyAt('00:05').

6
Print View

The Print for Approval button (see Section 4) uses window.print() with a @media print CSS block that hides everything except the print table. The printed sheet has blank approval/signature boxes at the bottom for boss to sign. No separate PDF library needed — browser print is clean enough.

7
Permissions (Spatie)

Add permissions: 'view payment schedule', 'approve payment schedule', 'reschedule payment', 'mark payment paid'. Only users with 'approve payment schedule' see the Approve/Reject buttons — boss gets this role.
