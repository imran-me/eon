01 Project summary

EON is an adaptive intelligence layer — not an application, not a chatbot, not an ERP feature. A portable reasoning core attaches to a system already running, learns it from its own source and database, and answers the people who depend on it — Bangla or English, voice or text, from live data, with the arithmetic behind every figure and the action it recommends next. Say yes, and it acts through the host's own screens.

The distinguishing decision: EON computes its answers; it does not generate them. No language model, no GPU, no per-query cost. Every sentence is arithmetic over a live database — fast, reproducible, auditable, free to run, and the data never leaves the server it lives on.

Proven in one demanding tenancy: a twelve-company commercial ERP, 203 tables, 293 screens — one of fifteen classes of Bangladeshi system with the same shape. What made the first work makes the next fourteen a configuration problem, not a rebuild.

What it is not

  • Not an ERP product. The ERP is the first host, not the subject. The reasoning core has no ERP in it.
  • Not a wrapper on a foreign model. Nothing is sent to an external endpoint. There is no endpoint.
  • Not a dashboard. A dashboard shows a figure. EON explains why the figure moved and what to do about it.
  • Not a translation layer. Bangla is not English output run through a translator — the reasoning itself runs in both languages.

EONThe four gaps02

02 Problem statement

Bangladesh has spent two decades successfully installing software. Ministries, banks, hospitals, factories and SMEs now run systems that record faithfully and at scale. The national problem is no longer recording. It is that recorded data does not become a decision without a trained human between the two — and there are not enough of them.

Gap 01 — decision

The data is present; the decision is absent

A system holds every figure a decision-maker needs and prints none of the reasoning. No screen says why profit fell, only that it did. No report ranks twelve companies, or qualifies itself when the data is incomplete. That gap is crossed manually, or not at all.

Gap 02 — language

The system speaks English; the country thinks in Bangla

The person accountable reasons in Bangla; every screen and report is in English. Machine translation does not close this: translated output carries English reasoning underneath, gets the numeric scale wrong (লাখ, কোটি), and cannot be read aloud — most machines have no Bangla voice at all.

Gap 03 — sovereignty

The obvious fix exports the nation's data

The default way to add intelligence is to send the system's contents to a foreign model API. A ledger, a patient list or a land record then leaves the country on every query, at a foreign-currency cost that scales with usage — and no answer can be audited, because the same question returns a different sentence tomorrow.

Gap 04 — integration

Adding intelligence usually means replacing the system

Forking, migrating or replacing the host each risks a working system, consumes a budget cycle, and breaks at the next upgrade. Institutions correctly refuse. So the systems most in need of an intelligence layer are the least able to accept one.

03 The proposed solution — one brain, many tenancies

EON closes all four with a single architectural idea: the intelligence does not own the system it serves — it rents a room in it.

ClosesHow, concretely
Decision gapAn invariant loop: read live data → decide what matters → detect risk and waste → rank the next action → explain the rule → act, on confirmation, reversibly. It does not change between hosts; only what it reads does.
Language gapBangla and English are parallel composition targets, not source and translation. Each answer is written natively in the language asked, on the Bangladeshi numeric scale, and rendered to speech server-side — so a machine with no Bangla voice still speaks Bangla.
Sovereignty gapNo model API. No GPU. No outbound call. The reasoning runs in PHP and SQL beside the host database, and the same question returns the same sentence every time because it is arithmetic.
Integration gapEON attaches by injection, not modification: one script tag appended by an output-buffer callback. M Zero lines of host source are edited; removing two files returns the host to exactly what it was.

Why this is the interesting claim

Most AI systems are judged on how well they generate. EON should be judged on the opposite: it cannot invent a number. Where two figures genuinely conflict it reports both and names the gap rather than quietly choosing one — and that habit of qualifying its own answer is the difference between a dashboard and an adviser.

Security is inherited, not invented

  • The database user is read-only.
  • Every endpoint is fail-closed — no session, no data.
  • Every write goes back through the host's own form and its own permission check. Nobody can ask EON for what the host would refuse them.
  • Money movements and deletions always require confirmation; a half-filled form stops rather than guessing.
  • A refusal from the host is read and reported as a refusal — a success code is not taken as success.

EONReasoning, not retrieval04

05 The path of a question

Nothing is queued and nothing is transmitted. The entire round trip happens on the host's own server.

01AskVoice or text. Bangla, English, or Banglish written in Latin letters.
02UnderstandIntent and language are read; anything unrecognised is parsed structurally instead.
03AnswerThe ledger is read, the rule applied, the figure decomposed until it is actionable.
04PhraseComposed natively in the language asked, on the Bangladeshi numeric scale.
05SpeakRendered to audio server-side and cached, so a repeat answer is instant.

It composes rather than enumerates

EON holds no list of supported questions. It scores the idioms people actually use; anything falling through is read structurally — a verb pointed at a subject, or a named record paired with an aspect.

So the capability surface is large without being hand-written: 45 subjects × 16 aspects × phrasings × 2 scripts compose to M 120,105 addressable question-points, a 1,500-point stratified sample of which answers at 100%.

It reasons about a figure until it is actionable

Asked "why is cash so tight?" — composed, not retrieved:

"Cash ৳1.89 L against a burn of ৳2.17 L a month — about 0.9 months, and 99% of that burn is payroll. ৳15.5 L is owed to you and all of it is past due. Against that you owe ৳20.7 L. So the gap is ৳17.8 L, and collecting every overdue taka would still not close it."

That last clause is what a decision-maker needs, and no report in any host system prints it. It is reached by decomposition — which of income, direct cost or overhead moved, and what is unapproved and therefore absent.

06 Where EON does not compromise

Six figures that do not move with scale, usage, or the sensitivity of the data. None is a policy commitment someone must audit and enforce — each is a property of the architecture: the thing that would break it does not exist in the system.

The trade being made, stated plainly

Because nothing is generated, a question outside the modelled grammar gets a refusal rather than a plausible paragraph — a real limitation, and the correct one for ledgers, patient records and land registers, where a confident wrong answer costs far more than no answer. A language model can be added later for phrasing; it is not needed for truth.

The published gaps — three closed, two open

A prototype that hides its edges cannot be evaluated. This list was published before anyone asked. Three entries are now closed and measured (24 Aug); the rest stand.

  • Closed — a question that narrows. The phrase is resolved against dimensions the data really carries; "in Chittagong" is refused, because no city column exists in the host.
  • Closed — comparison across periods. Cash and headcount are positions, not flows, so comparing them is declined out loud.
  • Closed — file export. The workbook is written in plain PHP — no library, no binary, no network call.
  • Still open — no free-form drafting beyond structured notices and reminders.
  • Still open, deliberately — rules are a calendar, not a rate card. VAT and TDS percentages are the accountant's to supply; a guessed rate is worse than an honest refusal.

10 It arrives already knowing the kind of system it is joining

Until now EON learned a host only by surveying it. That answers about this system; it does not arrive understanding what kind of system it is. Two generated corpora now carry that understanding — what a new host inherits on day one. Every business type is crossed with every module it really runs, and each fact is written in that trade's own word: a hospital reads "patient" where a university reads "student".

National alignment

  • Data sovereignty. No record leaves the server — a property of the architecture, not a promise to enforce.
  • No foreign-currency dependency. No token meter, no GPU rental. The only charge is installation.
  • Bangla as a first-class computing language — correct numeric scale, spoken on machines with no Bangla voice.
  • Reuse of public investment. Systems already paid for become more capable without being replaced.

Risks, pre-answered by the design: a host upgrade cannot conflict (nothing in the host is edited); a wrong answer cannot be generated (nothing is generated); data cannot leak (no outbound call); an unwanted action cannot fire (money and deletions always confirm); and coverage cannot look complete when it is not (every suite prints its failures).

An institution's software already knows everything. EON is the layer that makes it say so — in Bangla, on its own server, and with the arithmetic attached.

One tenancy of a system built to hold many. It is running today, measured rather than demonstrated, and it publishes what it cannot do. What it needs next is not a larger model — it is a second host.
